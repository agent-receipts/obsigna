Verify an Agent Receipts chain

Paste or load a receipt or chain and verify it here. The cryptographic checks run in WebAssembly compiled from the same Go verify core as the obsigna receipt verify CLI — there is no separate browser reimplementation, so what you run here matches what an auditor runs on the command line.

🔒
Everything runs in your browser. Receipts and keys you paste are never uploaded, never stored (not even in this browser), and never leave this page. After the verifier finishes loading, this page makes no network requests — you can confirm in your devtools Network tab.
External anchor proof (optional)

An anchor proof corroborates the chain head out of band and is what separates a full pass from a qualified one. Paste a signed checkpoint and the anchor public key it was signed with: when the checkpoint verifies and commits to this chain's head, the verdict rises to full. The anchor key is obtained and trusted separately from the issuer key.

This tool checks cryptographic properties only: signature validity, hash-chain integrity, and JCS (RFC 8785) canonicalization. It makes no claim of legal admissibility and does not attribute any action to a real-world person, organisation, or agent identity. A valid signature proves a chain is internally consistent under the public key you supplied — nothing more.

For what the verdicts mean, see the canonical spec pages: Trust model and Receipt chain verification.
